# 开发路线图

## 0. 阶段目标

路线图按“先闭环、再增强、最后工程化规模化”推进。当前最重要的是跑通 Android 真机、Appium 脚本、Agent 修复、Markdown 报告这一条最小闭环。

## 1. M0：项目骨架与文档

目标：建立工程方向和基础规范。

任务：

- 创建 docs 文档体系。
- 明确 Qt6 + Python + Appium + opencode 架构。
- 定义 Agent、Plugin、Skill 基础规范。
- 初始化推荐目录结构。
- 明确打包依赖清单。

验收：

- 文档完整。
- 项目成员能根据文档理解系统边界。

## 2. M1：Qt 主界面原型

目标：完成桌面端基础 UI。

任务：

- 左右分栏主界面。
- 左侧设备画面占位区。
- 右侧对话区。
- 附件列表。
- 任务进度列表。
- 状态栏显示设备连接状态。

验收：

- 应用可启动。
- 用户可以选择附件并发送消息。
- UI 不阻塞。

## 3. M2：设备连接与画面显示

目标：让手机真实接入。

任务：

- 集成 Android platform-tools。
- 实现 ADB 设备发现。
- 获取设备信息。
- 集成 scrcpy 画面显示。
- 支持截图。
- 支持基础输入操作。

验收：

- 插入手机后能识别设备。
- 左侧能看到实时画面。
- 能截图并保存到任务目录。

## 4. M3：Appium 运行时

目标：建立 Python + Appium 执行能力。

任务：

- 内置 Python 运行时。
- 内置 Node.js、JDK、Appium、UiAutomator2 driver。
- Runtime Manager 检查依赖。
- 启动 Appium Server。
- 创建 Appium Session。
- 执行最小点击测试。

验收：

- 用户无需安装 Appium。
- 能运行一个 Python Appium 脚本。
- 能采集失败截图和日志。

## 5. M4：附件解析

目标：让测试用例成为 Agent 上下文。

任务：

- 支持 `xlsx`、`csv`。
- 支持 `txt`、`md`。
- 支持 `docx`、`pdf` 的文本抽取。
- 生成统一用例 JSON。
- UI 展示解析摘要。

验收：

- 上传 Excel 后能识别用例 ID、步骤、期望结果。
- 解析失败时有明确错误提示。

## 6. M5：脚本生成 Agent

目标：通过 opencode 生成可执行脚本。

任务：

- 集成 opencode CLI。
- 实现 Agent Orchestrator。
- 将用户需求、用例、设备上下文传给脚本生成 Agent。
- 生成 Python Appium 脚本。
- 将脚本保存到任务目录。

验收：

- 用户一句话可以生成脚本。
- 脚本能被 Runner 执行。
- 生成过程可追踪。

## 7. M6：UI 理解与错误修复

目标：失败后能自动定位原因并修复。

任务：

- 采集当前 Activity。
- 采集当前 Fragment。
- 采集 Appium page source。
- 采集 Toast、Crash、ANR。
- UI 理解 Agent 输出页面状态。
- 错误修复 Agent 修改脚本。
- 最多自动重试 2 次。

验收：

- 控件找不到时能抓取截图和页面树。
- 能根据页面状态修改定位或等待逻辑。
- 不能修复时给出明确失败原因。

## 8. M7：测试报告与附件回填

目标：形成可提交产物。

任务：

- 生成 Markdown 报告。
- 统计成功率、失败原因、耗时。
- 插入截图和日志链接。
- 输出建议。
- 回填 Excel、Markdown、Word。
- PDF 附件生成旁路报告。

验收：

- 测试结束自动生成报告。
- Excel 用例表中能看到执行结果。
- 报告可直接提交或二次编辑。

## 9. M8：打包与免安装体验

目标：让非开发用户可直接使用。

任务：

- 打包 Qt 应用。
- 打包 Python、Node.js、JDK、ADB、scrcpy、Appium、opencode。
- 启动时运行自检。
- 首次启动引导授权 USB 调试。
- 生成诊断包。

验收：

- 新电脑解压或安装后可直接启动。
- 不要求用户手动安装 Python、Appium、JDK、Node.js。
- 缺失依赖时提示清晰。

## 10. M9：领域增强

目标：强化豆包眼镜连接测试。

任务：

- 蓝牙连接模板。
- 蓝牙连接耗时统计。
- 蓝牙断连重连测试。
- Wi-Fi 切换测试。
- 弱网和后台恢复测试。
- 眼镜设备识别策略。

验收：

- 可以稳定执行一组豆包眼镜连接回归用例。
- 报告能区分 App 问题、设备问题、环境问题和脚本问题。

## 11. 长期规划

- 多设备并发测试。
- 测试任务队列。
- 真机云接入。
- 本地模型或企业私有模型适配。
- 团队共享插件市场。
- 测试报告仪表盘。
- 与缺陷管理系统对接。
