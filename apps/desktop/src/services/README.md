# Desktop Services

放置 Bridge 客户端、设备会话客户端、附件客户端和任务事件流客户端。UI 通过这些接口访问后端能力。

当前 `ScrcpyService` 负责：

- 使用 scrcpy 同目录的 `adb.exe` 轮询设备状态。
- 按主屏幕、虚拟屏幕或摄像头配置启动独立 scrcpy 镜像窗口。
- 查询设备摄像头，并为录制、启动应用和高级参数提供结构化参数入口。
- 跟踪进程状态并支持停止镜像。
- 将启动失败和异常退出反馈给 UI。

`DisplayService` 负责：

- 异步读取分辨率、密度、屏幕超时、刷新率、深色模式、字体和动画缩放。
- 串行执行显示设置动作，并在成功后回读设备状态。
- 校验显示参数，避免无效数值进入 ADB 命令。

`AdbControlService` 负责：

- 将 KEYCODE 转换为参数化的 `adb shell input keyevent` 调用。
- 串行执行连续点击产生的命令队列。
- 执行经过确认的设备重启命令。
- 执行经过确认的 `adb shell reboot -p` 关机命令。
- 向设备控制页返回开始、成功和失败状态。

`ProcessService` 负责：

- 异步缓存已安装软件包并按 5 秒周期采样设备 `top`。
- 解析进程名称、CPU、CPU 时间、内存、PID 和用户，并标记应用进程。
- 仅在进程工作区激活时采样，离开页面或切换设备后停止当前查询。
- 对用户确认的应用执行 `am force-stop` 并回传结果。

`OtherService` 负责：

- 异步执行其它工具页提交的单条 Android Shell 命令。
- 处理设备切换、ADB 缺失、并发操作和进程异常。
- 将命令开始状态、标准输出和失败信息返回 UI。
